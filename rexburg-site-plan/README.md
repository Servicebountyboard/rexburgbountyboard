# Rexburg Bounty Board site plan

Open `site-plan.html` in any browser. No installation, JavaScript, external fonts, or network connection is required.

## Files
- `site-plan.html`: purpose, audience, branding, style guide, navigation, sitemap, workflows, six mobile wireframes, desktop layout, screen requirements, and team handoff.
- `styles/site-plan.css`: editable design tokens and responsive layouts. Change the variables at the top to adjust the theme.

This is planning documentation, not a functioning bounty app. Mock actions are static text samples; section links and expandable source notes work. The sample description field is editable but not saved. Nothing is submitted to a server.

## Team editing
1. Add names and class section in the header (look for `TEAM`).
2. Review the decision register with the business/data members.
3. Keep required SRS behavior separate from proposed enhancements.
4. Update sample content and wireframes as decisions are approved.
5. Copy the entire folder into your repository; retain the `styles` directory beside the HTML.

Sources: supplied Rexburg_Bounty_Board_SRS_Outline.docx and wwr_project.zip site-plan-rafting example. Includes the agreed tavern concept. No original attachments or unrelated rafting assets are redistributed.

Google/Apple sign-in, scoring, rating scale, notification implementation, messaging implementation, address visibility, and additional profile features remain undecided. CSS wireframes can guide the SRS's future Figma work; no Figma file is included.
